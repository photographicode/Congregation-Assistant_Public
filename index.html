Questions

Frequently asked.

How is the data stored?

The current build uses a cloud database connection for congregation records, while the browser stores certain session and preference information locally. The application separates congregation records by congregation ID. The exact hosting, retention and backup policy should be confirmed with the service provider before production use.

Will my congregation's data be private?

Privacy is a core goal. The congregation should control its own account credentials, and the developer does not need the congregation's day-to-day password for normal use. Because this is a hosted web application, complete privacy also depends on the final hosting, database permissions, security rules and operational policy used for the production deployment. Those details can be documented before launch.

How do we receive our account?

After the congregation is set up, the administrator can be provided a congregation ID and a temporary password. The administrator can then sign in and change the password to one known only to the congregation. Setup or system notifications can also be sent when applicable.

Can the administrator change the password?

Yes. The current build includes a Change Password workflow with password-strength requirements. A temporary password can therefore be replaced by the congregation administrator after the initial setup.

Can we take our own backup?

Yes. The current build provides Export Contacts and Export Reports. These exports can be saved by the congregation as offline backup copies. A separate full-database disaster-recovery backup policy should be agreed on for production hosting.

Do we need to install any software?

No separate software installation is intended. Congregation Assistant is designed as a web application, so the normal workflow is to open it in a modern web browser. This makes it easier to use across computers, tablets and phones.

Can publishers submit information themselves?

Yes. The current build includes public-facing submission workflows and copyable public links for monthly field service reporting, so publishers do not need access to the administrator dashboard just to submit a report.

Can group overseers have their own access?

Yes. The current build includes a password-protected Group Overseer Portal and copyable overseer links. Group passwords can be set and changed separately.

Will the system send notifications?

The current build includes system notifications that can be sent to selected congregations from the administrative control center. Additional notification workflows can be added as the platform grows.

What about a congregation invitation?

The onboarding flow can include a congregation invitation/setup message containing the information needed to access the account. The exact invitation and notification process can be finalized for the production version.

Will more features be added?

Yes. Planned future areas include Territory Management, OCLM Scheduling, expanded administrative automation, additional reporting and other tools requested by congregations.

What if our congregation cannot afford the listed price?

Please contact us. If the standard price is difficult for your congregation, we are open to discussing a lower-cost arrangement based on the circumstances.
